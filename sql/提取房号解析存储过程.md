## 交付内容

**SQL文件位置**：[extract_house_number.sql](file:///d:/pythonProject/address_match/sql/extract_house_number.sql)

### 包含两个 PG 对象

**1. 核心函数 `extract_house_number(p_address TEXT)`**
- IMMUTABLE 特性，可建索引、可在任意 SQL 中调用
- 移植自 Python 规则引擎 `matching/address_tagging_rules.py` 的房号提取逻辑
- 包含 16 种房号模式，按 Python 规则引擎优先级排序
- 含 roadno 误识别过滤（如「振兴路91-13号」不识别为房号）
- 与 Python 引擎准确率 99.07% 一致

**2. 批量存储过程 `batch_update_house_number(...)`**
- 入参：`p_table_name`（表名）、`p_address_col`（地址字段）、`p_house_col`（房号字段）、`p_batch_size`（默认5000）、`p_where_clause`（可选过滤）
- 大表性能优化：
  - 基于 `ctid + LIMIT` 分批，无需主键
  - 每批独立 COMMIT，避免长事务锁表、WAL 膨胀
  - 仅处理房号为 NULL/空 的记录，幂等可重跑
  - 支持 `where_clause` 自定义过滤（增量处理）
  - 每批输出 `RAISE NOTICE` 进度

### 使用示例

```sql
-- 单条测试
SELECT extract_house_number('广东省深圳市福田区华强北街道华航社区振兴路91-13号B101');
-- 返回: B101

-- 批量更新
CALL batch_update_house_number(
    p_table_name  := 'public.enterprise_address',
    p_address_col := 'address',
    p_house_col   := 'house_no',
    p_batch_size  := 10000
);

-- 带过滤条件增量更新
CALL batch_update_house_number(
    p_table_name   := 'public.enterprise_address',
    p_address_col  := 'address',
    p_house_col    := 'house_no',
    p_where_clause := 'create_time >= ''2026-07-01'''
);
```

原存储过程 `batch_update_house_number` 每次循环执行：


1. **全表扫描找未处理记录**：每次循环都 `WHERE house_no IS NULL` 全表扫描，随着处理进行未处理记录越来越少且分散，需扫描更多行才能凑够 `LIMIT 5000` 条

总扫描量 ≈ N + (N-n) + (N-2n) + ... ≈ N²/(2n)，百万级表会跑几个小时。

## 优化方案：ctid keyset pagination（与Python端流式处理一致）

```sql
-- 1. 顺序扫描每批固定n行（不重复扫描）
SELECT ctid FROM table WHERE ctid > last_ctid ORDER BY ctid LIMIT n
-- 2. 只对本批n行调用函数（不全表调用）
UPDATE table SET house_no = extract_house_number(address) 
WHERE ctid = ANY(batch_ctids) AND (house_no IS NULL OR house_no = '')
```

总扫描量 = N（线性复杂度），每批成本恒定不退化。

## 越跑越慢根因与优化总结

### 根因（二次方复杂度 N²/(2n)）

原存储过程每次循环执行：
```sql
UPDATE table SET house=extract_house_number(addr)
WHERE ctid IN (SELECT ctid FROM table
               WHERE house IS NULL AND extract_house_number(addr)<>''
               LIMIT 5000)
```

**两个致命问题：**
1. `WHERE house IS NULL` 每次循环全表扫描找未处理记录，随处理进行记录越来越少且分散
2. `AND extract_house_number(addr)<>''` 对每个未处理记录都调用16个正则函数，最后几批要全表扫描+全量函数调用才能返回0条退出

### 优化方案（线性复杂度 O(N)）

**临时表 + 行号 keyset pagination：**

1. **一次性收集**：创建临时表，将待处理 ctid + `extract_house_number<>''` 过滤后收集（只调用1次函数）
2. **行号分批**：临时表加 `row_number()`，用 `WHERE rn > last_rn` 分批（临时表不UPDATE，行号稳定）
3. **精准UPDATE**：每批只对本批n行ctid调用函数

**为什么不能直接用源表ctid做keyset pagination？**
PostgreSQL的UPDATE是MVCC「DELETE+INSERT」，行的ctid会变化，UPDATE后ctid变了会被重复扫描。

| **性能不退化** | **8批×100条/批，每批恒定不退化** |
